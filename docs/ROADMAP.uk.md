# Roadmap HitTracker

[English](ROADMAP.md) · **Українська**

## Заплановано: справжній monorepo

Поточний центральний репозиторій навмисно є центром документації. Вихідний код mobile та backend залишається в наявних репозиторіях, доки контрольована міграція не стане доцільною.

### Цільова структура

```text
HitTracker/
├── mobile/
├── backend/
├── docs/
├── .github/
└── README.md
```

### Чому міграцію відкладено

- Обидва репозиторії вже мають незалежну історію та робочі remotes.
- Android-релізи зараз однозначно пов'язані з комітами вихідного коду mobile.
- Deployment- і Docker-шляхи посилаються на поточну структуру сусідніх каталогів.
- Передчасне дублювання файлів створило б кілька суперечливих джерел правди.

### Чекліст міграції

- [ ] Вибрати остаточного власника репозиторію та права учасників.
- [ ] Створити резервні копії обох репозиторіїв і перевірити чистий стан робочих дерев.
- [ ] Перевірити відстежувані файли та правила ігнорування перед імпортом кодових баз.
- [ ] Імпортувати історію mobile та backend у `mobile/` і `backend/` без втрати авторства.
- [ ] Перенести спільну архітектурну й продуктову документацію до `docs/`.
- [ ] Оновити Docker Compose paths, scripts, документацію та deployment-конфігурацію.
- [ ] Додати перевірки рівня репозиторію для mobile та backend без зміни їхніх framework-specific команд.
- [ ] Вирішити, чи залишити історичні APK-релізи пов'язаними з mobile-репозиторієм, чи скопіювати їх до monorepo.
- [ ] Перевірити web, API, міграції бази даних і Android release-збірки з чистого clone.
- [ ] Змінити remotes розробників лише після успішної перевірки.
- [ ] Архівувати старі репозиторії лише після перевірки всіх посилань, релізів і deployment-процесів.

### Рекомендований момент для початку

Почніть міграцію після стабілізації дипломного релізу або коли підтримка змін між кількома репозиторіями стане регулярною проблемою. Не варто мігрувати лише заради візуальної організації: цей hub уже надає єдину публічну точку входу без втручання в робочий код.

## Інші заплановані роботи

- Завершити аналітику тренувань та екрани прогресу.
- Додати production-хостинг, незалежний від комп'ютера розробника.
- Додати автоматизовані перевірки для обох репозиторіїв.
- Підготувати публікацію Android App Bundle для магазину та підпис iOS, коли з'являться відповідні облікові записи.
